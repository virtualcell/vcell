## Project background

`vcell-fenics` explores **DOLFINx 0.10 (modern FEniCSx, not legacy `dolfin`)** as a backend for moving-membrane cell-migration problems, in the Virtual Cell context. Its central idea is *"one math description, many solvers"*: a model is written as a declarative **MathDescription** (templates + a small expression language, in `formalism/`), realized onto a mesh via a **Geometry** description, and compiled to UFL/PETSc by a DOLFINx **backend** (`backend/`). A `pyvcell_bridge` package imports VCell's lowered VCML math model (via the sibling `pyvcell` repo's pure-Pydantic data model) so existing VCell BioModels can be re-solved on the FEM stack and cross-checked against VCell's finite-volume solver. The physics target is the canonical reaction-diffusion-on-a-deforming-membrane problem — surface densities ρ with the mandatory stretch-dilution term `ρ ∇_Γ·v_Γ`, coupled to bulk cytosolic fields — drawn from the Contri-Massing-Rangamani 2025 paper named in the docs as the scientific "North Star." Pure Python (~1.3 MB), conda-forge stack managed by **Pixi**, no CI/release machinery in place.

## Timeline (June 2026, the single sprint)

**Membrane mechanics & ALE foundations (#1-#20, Jun 14-15).** The repo opens already past scaffolding: [#1](https://github.com/virtualcell/vcell-fenics/pull/1) lands a "weak-form escape hatch" plus 29 files of membrane mechanics, and the next two days build out the moving-membrane machinery — curvature forces ([#3](https://github.com/virtualcell/vcell-fenics/pull/3)), a BGN tangential mesh-redistribution kernel ([#4](https://github.com/virtualcell/vcell-fenics/pull/4)/[#5](https://github.com/virtualcell/vcell-fenics/pull/5)), ALE coupling for a co-moving receptor ([#6](https://github.com/virtualcell/vcell-fenics/pull/6)), and the Eulerian `relative_advection` term ([#8](https://github.com/virtualcell/vcell-fenics/pull/8)). A multiphase-cytoplasm track follows: Nitsche normal-slip BCs, two-phase overdamped flow, incompressible Stokes via Taylor-Hood, and mass-conserving H(div) Stokes as an "FSI conservation fix" ([#10](https://github.com/virtualcell/vcell-fenics/pull/10)-[#18](https://github.com/virtualcell/vcell-fenics/pull/18)).

**FSI loop, reactions, and the declarative formalism (#19-#41, Jun 15-17).** A dynamic fluid-structure-interaction loop closes ([#19](https://github.com/virtualcell/vcell-fenics/pull/19)/[#20](https://github.com/virtualcell/vcell-fenics/pull/20)), then multiple reacting volume species are wired into the moving two-phase cell ([#21](https://github.com/virtualcell/vcell-fenics/pull/21)-[#23](https://github.com/virtualcell/vcell-fenics/pull/23)). A method-of-lines RDA integrator on PETSc TS arrives ([#25](https://github.com/virtualcell/vcell-fenics/pull/25)), alongside a **validation/diagnostics layer** ([#29](https://github.com/virtualcell/vcell-fenics/pull/29)-[#36](https://github.com/virtualcell/vcell-fenics/pull/36): inf-sup element-pair checks, a-priori nonlinearity checks, t=0 residual pre-flight). [#37](https://github.com/virtualcell/vcell-fenics/pull/37)/[#38](https://github.com/virtualcell/vcell-fenics/pull/38) prototype a Cahn-Hilliard diffuse-interface solver. The pivotal architecture step is [#40](https://github.com/virtualcell/vcell-fenics/pull/40) (namespaced built-ins, ADR 006) and **[#41](https://github.com/virtualcell/vcell-fenics/pull/41) — the VCell import layer `pyvcell_bridge`** (43 files, +2813): it translates pyvcell's lowered `MathDescription` (CompartmentSubDomain→volume, MembraneSubDomain→surface, PdeEquation→bulk/surface templates, JumpCondition→interface flux) into the formalism, inlining VCell `MathFunction`s and surfacing them as observables.

**Geometry formalism + FV cross-validation (#42-#75, Jun 18-22).** A geometry source-of-truth formalism (ADR 007, [#43](https://github.com/virtualcell/vcell-fenics/pull/43)/[#44](https://github.com/virtualcell/vcell-fenics/pull/44)) introduces GeometryDescription, an Rvachev analytic-predicate→implicit-function lowering ([#48](https://github.com/virtualcell/vcell-fenics/pull/48)), and a 2D body-fitted realization that cross-checks against VCell's region masks ([#50](https://github.com/virtualcell/vcell-fenics/pull/50)). Per-face and membrane-jump BCs are imported from VCell ([#52](https://github.com/virtualcell/vcell-fenics/pull/52)/[#53](https://github.com/virtualcell/vcell-fenics/pull/53)). The validation milestone is **[#54](https://github.com/virtualcell/vcell-fenics/pull/54) — end-to-end numerics comparison vs VCell's FV solver** (22 files), with the FV solver as ground truth on a common VCML; follow-ups confirm membrane jump-condition sign conventions ([#55](https://github.com/virtualcell/vcell-fenics/pull/55)), time-dependent flux ([#56](https://github.com/virtualcell/vcell-fenics/pull/56)), and FV/FEniCSx convergence ([#58](https://github.com/virtualcell/vcell-fenics/pull/58)). Bulk-bulk and membrane-species coupling is generalized ([#64](https://github.com/virtualcell/vcell-fenics/pull/64)-[#72](https://github.com/virtualcell/vcell-fenics/pull/72)), culminating in importing a **real public moving-boundary BioModel (RacRho neutrophil)** and validating receptor-binding MOL against `fvsolver` ([#75](https://github.com/virtualcell/vcell-fenics/pull/75), [#85](https://github.com/virtualcell/vcell-fenics/pull/85)/[#86](https://github.com/virtualcell/vcell-fenics/pull/86)).

**Migration loop, phase-field verification, and honest reframing (#76-#104, Jun 22-25).** Mechano-chemical coupling closes a self-organizing chemotaxis loop ([#80](https://github.com/virtualcell/vcell-fenics/pull/80)-[#82](https://github.com/virtualcell/vcell-fenics/pull/82)), and Cahn-Hilliard is verified against the spinodal dispersion relation and the Gibbs-Thomson droplet-curvature relation with a mesh-convergence integration test ([#93](https://github.com/virtualcell/vcell-fenics/pull/93)-[#95](https://github.com/virtualcell/vcell-fenics/pull/95)). Notably, [#96](https://github.com/virtualcell/vcell-fenics/pull/96) **reframes a LEGI chemotaxis demo "honestly: it senses, it does not migrate (yet)"** — a candid walk-back of an over-claimed result, repeated in commit messages. The sprint ends on moving-boundary translation cross-validation against VCell's FronTier FV moving-boundary solver ([#99](https://github.com/virtualcell/vcell-fenics/pull/99)-[#103](https://github.com/virtualcell/vcell-fenics/pull/103)) and a mypy/ruff cleanup of examples ([#104](https://github.com/virtualcell/vcell-fenics/pull/104)).

## Tech & stack notes

- **Language:** 100% Python (~1.3 MB), `requires-python >= 3.12`.
- **FEniCS flavor:** **DOLFINx 0.10.x** (modern FEniCSx) — explicitly *not* legacy `dolfin`. Pinned because native mixed-dimensional assembly landed in 0.10 (ADR 002). Plus `petsc4py`, `scifem`, `dolfinx_mpc`, `gmsh`, `meshio`, `pyvista`, `scikit-image`.
- **Env/build:** **Pixi** (conda-forge channels, `osx-arm64`+`linux-64`), hatchling wheel build, committed `pixi.lock`. MPI = MPICH (ADR 003). Quality gate `pixi run -e dev check` = ruff + mypy `--strict` + pytest; ships `py.typed`.
- **VCell integration:** `pyvcell >= 0.4.0,<0.5` as a normal pixi dep (pure-Pydantic VCML model only; heavy solver/viz extras excluded). Cross-validation drives VCell's `fvsolver` / moving-boundary (FronTier) solvers in the sibling `pyvcell` env and compares fields point-by-point — VCell FV is treated as ground truth.
- **Architecture:** four candidate FE approaches documented (A: ALE explicit membrane, B: separate-mesh/mixed-dimensional, C: phase-field/Cahn-Hilliard, D: cut/trace FEM via CutFEMx — D deferred, needs DOLFINx 0.9). Modules: `formalism/` (declarative math IR + parser + validator), `backend/` (UFL compiler, DiscreteProblem IR, solvers), `core/` (mesh redistribution/remeshing), `pyvcell_bridge/` (VCML import), `approaches/` (static/submesh/multicompartment geometries).
- **CI/Release:** **none** — 0 releases, 0 tags, no GitHub Actions. README is a one-line stub; the real documentation is `docs/` (7 ADRs, modeling notes, 3 demo notebooks) and `CLAUDE.md`.
