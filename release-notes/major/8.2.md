# VCell 8.2

**Released:** in progress. The first build was **8.2.0.01** (2026-09-25, dev
site), with the headline features off by default behind the feature gates
`vcell.fenics.enabled` and `vcell.fieldViewer.enabled`. **From 8.2.0.02
(2026-09-27) both are on by default.** This narrative becomes the vcell.org entry when
prod rolls to 8.2; until then it is a draft.

## Headline

**A finite-element solver that follows the shape of the cell.**

VCell's spatial solvers work on a Cartesian grid: the cell's boundary cuts
across grid cells, and moving boundaries are limited to 2D. VCell 8.2 adds
**FEniCSx**, a finite-element solver that meshes the cell itself. The mesh
follows the membrane, can move with it in 2D and in 3D, and can be built from a
segmented image. Its results open in a new browser field viewer that draws the
actual mesh.

## What's new

### FEniCSx, a body-fitted finite-element solver

FEniCSx appears in a spatial simulation's solver list next to the
finite-volume solvers. It takes the same model and the same simulation
settings, meshes each compartment's geometry, and solves reaction–diffusion
(and advection) on that mesh. It runs locally in Docker for a quick run and on
the VCell cluster for a full run. VCell refuses the run up front, with a reason,
for a model FEniCSx can't handle, rather than letting it fail part-way.

### Moving boundaries, now in 3D

Moving-boundary applications, whose membrane moves with a velocity you
prescribe in Kinematics, run on FEniCSx in 2D and 3D. The mesh moves with the
membrane and is rebuilt when it becomes too distorted, and species are
conserved across each rebuild. In 3D the kinematics table offers the Z
components of the velocity, which were hidden before. The older Moving
Boundary solver remains available for 2D and now declines 3D models it could
not solve correctly.

### Many compartments

A model can have any number of compartments and membranes: a nucleus inside a
cytosol inside extracellular space, organelles, or two cells side by side.
Each membrane couples the compartments on its two sides, with species,
membrane species (receptors, channels), and well-mixed species or a membrane
potential on any of them. Compartments may touch the edge of the domain, and
three may meet at a point.

### Image-based geometries

A geometry made from a segmented 2D or 3D image becomes a smooth, body-fitted
mesh instead of voxel steps. This includes nested compartments, regions cut by
the image edge, and junctions where three compartments meet.

### A browser field viewer

FEniCSx results open in a field viewer in your browser. It draws the solver's
own mesh:
- with or without its edges, or as a wireframe;
- sliced at a plane, either as a smooth cross-section or cell by cell;
- following a moving mesh frame by frame.

Click any point to plot its time course, and shift-click to add more points:
each gets its own trace in one plot. Draw a line with the Line tool to see a
kymograph, the variable along the line at every saved time. Time plots and
kymographs work for finite-volume, FEniCSx, Chombo and MovingBoundary results,
and along membranes; on finite-volume results a kymograph matches the desktop's.
They export as CSV, and a kymograph as PNG. A kymograph has a time crosshair
and a space crosshair, as in the desktop, with the variable along the line at
that time, and over time at that point, plotted below it. Drag to rotate;
shift- or right-drag to pan.

## Improvements

- VCell's native solvers now come from their own repositories, and on a Mac with Apple silicon they all
  run natively, without Rosetta. The Hybrid solvers now run locally on Windows, macOS and Linux,
  MovingBoundary on Windows and Linux as well as macOS, and Chombo on macOS and Linux.
- Rule-based help pages describe the current molecule, observable and
  species-pattern colors, and there is a new SpringSaLaD definition.

## Bug fixes

- Saving a model from Windows no longer garbles non-ASCII text in annotations (μ, superscripts, accented
  letters). Each save from Windows used to double such text, until a model could become too large to save.
- The Hybrid Milstein and adaptive Milstein solvers ran the Euler method; each now runs its own method.
- Rule-based models work on the server: math generation and BNGL download no
  longer fail looking for BioNetGen.
- Downloading BNGL for a BioModel with no applications returns a clear "no
  applications" answer instead of a server error.

## API and integration changes

- No `/api/v1/` schema changes.
- `/api/v0/biomodel/{id}/biomodel.bngl` returns 404, not 500, for a BioModel
  with no applications.

## Known issues

- FEniCSx runs on a single process (no MPI yet).
- Well-mixed species or a membrane potential in a model whose species all live
  in one compartment, or in a moving-boundary model, are not supported yet;
  FEniCSx stops such a run at its start with a message saying why.
- Models with a FastSystem (rapid-equilibrium buffering) run only on the
  finite-volume solvers; FEniCSx refuses them.
- CSG geometries, and image geometries in moving-boundary applications, are not
  supported yet.
- The field viewer needs a current browser: Safari 26 or later, Chrome or Edge
  137 or later, or a current Firefox. An older browser shows a message saying so,
  with the page's address to open in another browser.
