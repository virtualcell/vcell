# VCell 7.7 — Initial Release

**Released to production:** 2024-09-27 (build 7.7.0.0), with patch
rollouts to 7.7.0.9 (2024-12-04) and 7.7.0.15 (2025-02-17).

The first of three release events on the VCell 7.7 line. This
release introduced Java-native plotting in the command-line
interface, an early redesign of the SpringSaLaD modeling interface,
the foundations of the new Quarkus REST API, modernized HDF5
handling, OIDC/Auth0 authentication for the client, and the first
of the parameter-estimation and Field Data REST endpoints.

## What's new

### Java-native plotting in the VCell CLI

VCell's command-line interface previously generated plots by
calling into a Python live-shell from Java — a fragile bridge that
caused speed and debugging problems. The Python live-shell was
removed and replaced with a Java-based plotting library. The
Python plotting bridge is deprecated.

### Redesigned SpringSaLaD interface (first pass)

> **SpringSaLaD availability in 7.7.** SpringSaLaD was released in
> VCell 7.7 under a feature flag for beta testing — available to
> users who explicitly enabled it, and on by default in
> non-production deployments. On the production release site the
> flag was off by default. The feature flag is removed in
> **[VCell 8.0.0](./8.0.0.md)**, where SpringSaLaD is enabled
> across all deployments as a first-class modality.

The SpringSaLaD-specific user interface received its first major
overhaul during this release window:

- New molecular-structure properties panel
- Tables and table-models for site attributes and links
- Large-shape representation of site attributes in the
  species-context view
- Editable links in the molecular-structure tables
- Filter for SpringSaLaD simulation results, with trivial-data
  result sets highlighted
- Multi-run controls: "Number of Trials" and "Random Seed" for
  Langevin simulations (first version)
- Stricter integrator filtering — solver-choice dropdowns now hide
  integrators unsuitable for SpringSaLaD applications

### Initial Quarkus REST API endpoints

The first of the new `/api/v1/` endpoints landed during this
window, beginning the migration from the legacy Restlet framework:

- Field Data endpoint set (get IDs, analyze, create, delete)
- FVSolver input generation from VCML
- OIDC / Auth0 authentication framework
- User-authentication middleware overhaul: anonymous "VCell guest"
  is no longer threaded through every endpoint
- `users-query` admin CLI command for listing users who ran
  simulations since a start date

### Modernized HDF5 handling

The legacy native HDF5 library was replaced with a pure-Java
implementation (`io.jhdf`) for non-spatial HDF5 writes during
OMEX execution. This eliminates a class of native-library
compatibility issues across platforms.

### Native pyvcell foundations

Initial native compilation of `vcell-nativelib` was set up for the
pyvcell Python client, with deployment routed through the separate
`libvcell` repository. This is the foundation for stand-alone
Python access to VCell data and simulation primitives.

## Improvements

- BioModel opening: any BioModel can now be opened unless it is a
  duplicated leaf.
- Legacy "Annotations" now sync with formal annotations in
  simulations.
- KiSAO ontology refreshed; new KiSAO_694 parsing added.
- Simulation `JobIndex` redefined in terms of `ScanIndex` and
  `TrialIndex` to support multi-trial Langevin runs.
- Trivial `numTrials` value (1) no longer saved to XML/VCML.
- Geometry viewer cropping correctness.
- Server-side biosim log written directly from Java, with a fast
  in-memory variant.
- HTML help: generation fix and dead-link repair pass.

## Bug fixes

- Membrane Langevin jump processes load correctly from VCML.
- Export Service no longer holds old state across runs.
- Local export of simulation results restored.
- Client requests focus after OIDC login/logout flow.
- Observable-generation performance: rewrote the network
  transformer paths so generation no longer takes
  disproportionately long during rule-based-model save / network
  flatten.
- SBML reserved-character reaction names mangled correctly
  (e.g., `x` → `RESERVED_x`).
- SBML structure names accommodated on import; passes
  BIOMD0001-0071.
- Infinity and NaN supported in SBML values and MathML.
- Different jump processes correctly reported in math description.
- OMEX manifest separator fixed on Windows.
- OMEX execution failure for repeated tasks of size 1.

## What followed

VCell 7.7 stayed on the release site at 7.7.0.15 for roughly a
year, while substantial new functionality was developed. That work
landed in production as the next release event:
[VCell 7.7 — Feature Update](./7.7-feature-update.md).
