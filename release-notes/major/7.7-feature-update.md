# VCell 7.7 — Feature Update

**Released to production:** 2026-02-04 (build 7.7.0.47).

The second of three release events on the VCell 7.7 line. After
VCell 7.7 spent roughly a year stable on the release site at
7.7.0.15, this release delivered approximately 32 builds of
accumulated development to production users in a single rollout.
The headline themes: completion of the new Quarkus REST API
surface, removal of the long-standing requirement for
administrator privileges to install the VCell client, the
modernized parameter-estimation service, and the introduction of
generalized stochastic simulation for non-mass-action reactions.
Substantial SpringSaLaD development also landed during this
window — SpringSaLaD was available under a beta-test feature flag
throughout the 7.7 line (on by default in non-production
deployments, off by default on the release site). The feature
flag is removed in **VCell 8.0.0**.

## What's new

### Install VCell without administrator privileges

The VCell client can now be installed without administrator
privileges on the user's machine. This closes a long-standing
request from users at institutions that lock down end-user
machines, where every VCell update previously required a call to
IT support. The looser installation requirement is intended to
reduce friction for the team to ship more frequent updates.

### Generalized stochastic simulation of non-mass-action reactions

VCell's Gillespie stochastic solver previously supported only
reactions defined as Mass-Action kinetics. With this release,
VCell can now run exact Gillespie stochastic simulations on a
broader set of non-mass-action reaction kinetics, expanding the
class of models amenable to stochastic analysis.

### REST API on Quarkus — full endpoint set

The migration of VCell's REST API from the legacy Restlet
framework to Quarkus reached completion. The full set of
`/api/v1/` endpoints is now in production:

- **BioModel** — save, retrieve, delete, info (with JSON
  serialization of Version, GroupAccess, PublicationInfo)
- **MathModel** — info retrieval, save, delete, get
- **Geometry** — modify and retrieve VCML geometry
- **Image (VCImage)** — resource endpoints
- **Field Data** — full lifecycle (upload, analyze, create from
  simulation results, copy from BioModel, delete)
- **Publications** — `PUT /api/v1/publications/{id}/publish` for
  marking BioModels and MathModels as published. On publish, the
  models' `GroupAccess` is set to `GroupAccessAll` (public read)
  and `VersionFlag` is set to `Published` (curation status).
  Selective publishing of specific model keys is supported.

OIDC authentication via Auth0 is required for `/api/v1/`. The new
user-authentication middleware no longer threads an anonymous
"VCell guest" user object through every endpoint; specific
endpoints may still permit anonymous access where appropriate
(for example, public-publication reads).

The OpenAPI spec is now generated by Quarkus SmallRye OpenAPI and
lives at `tools/openapi.yaml`. Java, Python, and TypeScript-Angular
clients are auto-generated from it. CI verifies the spec is stable
on every pull request.

### Centralized API error handling

A standardized `VCellHTTPError` response object replaces ad-hoc
error returns from the new API. Endpoints declare their expected
error types, errors are emitted from a factory, and the error
schema is included in the generated OpenAPI spec.

### SpringSaLaD beta — multi-run + SLURM array execution

> **SpringSaLaD availability in 7.7.** SpringSaLaD was available
> under a feature flag for beta testing throughout the 7.7 line —
> enabled by default in non-production deployments where the team
> and beta testers worked with it, and off by default on the
> production release site. The feature flag is removed in
> **[VCell 8.0](./8.0.md)**, where SpringSaLaD is enabled
> across all deployments.

The SpringSaLaD development that landed in this window gave the
modality robust multi-run capability:

- Concurrent Langevin runs are dispatched as SLURM array jobs on
  the compute cluster
- Batch simulation results transfer from server back to the
  desktop client
- Physical-limit checks for site size, diffusion rate, and
  partition size before submission
- Particle-displacement calculation: given diffusion rate, time
  step, and probability, computes the max distance a particle
  can travel — used to refine binding-event detection across
  partition boundaries

### Field Data — REST-API rewrite

The Field Data system migrated to dedicated REST endpoints,
including the ability to:

- Derive Field Data from simulation results
- Copy Field Data between BioModels
- Upload and analyze field-data files
- Operate on field data via the new `/api/v1/` endpoints

The algorithm that analyzes uploaded field-data files moved from
client-side to server-side execution, with memory-management
improvements that fixed failures on large files. The legacy
"Field Data Specs" abstraction was removed in favor of the new
endpoints.

### Parameter estimation on Quarkus

Parameter estimation migrated to the new REST API with
database-backed job tracking: estimation jobs and their status
are persisted across server restarts. The CLI reuses a single
authenticated connection across requests instead of triggering
a re-login per request, fixing the prior "Parameter Estimation
Results in Login Request" issue.

### Pathway Commons annotation lookup, restored

Pathway Commons annotation lookup was upgraded to the new Pathway
Commons URLs and feature set. The list of pathways and most
entity types load again; reaction loading remains incompatible
with the VCell internal model.

### VCell Alert blinking-icon enhancement

The desktop client's alert blinking-icon now displays the alert
title alongside the icon, pulled from
`https://vcell.org/webstart/VCell_alert/VCell_Alert.html`. The
message fades when the icon stops blinking, about a minute after
the client opens.

### New SLURM cluster migration

VCell's compute backend migrated to a new SLURM cluster with:

- SSH command options configurable from Kubernetes ConfigMaps
- SLURM node read from a property setting
- Default Singularity binary path standardized on the batch-run
  node

### Tooling and developer ergonomics

- New `vcell-nativelib` native compilation pipeline, deployed via
  the separate `libvcell` repository.
- Langevin solver upgraded across the window (1.4.0 → 1.4.2 →
  1.4.4).
- Python expression syntax in VCell expressions (foundation for
  PyVCell infix support).

## Improvements

- Geometry tab UI: "Constructed solid geometry" label corrected
  to "Constructive solid geometry".
- External links rendered in parentheses in annotation displays.
- Mac installer packaging: duplicate-installer copy/send flow.
- BioModel save: KeyValue serialization changed from object to
  string form, fixing a save bug surfaced after the move to the
  Quarkus save endpoint.

## Bug fixes

- `MathSymbolMapping` `TreeMap` concurrent-modification NPE.
- NPE when inserting a compartment.
- Membrane reactions placed at correct location.
- Math Model Export Error.
- `OutputFunctions` no longer ignored.
- VCell connection failure on transient errors.
- Export test failure under the Quarkus CDI context.
- Langevin input file particle-location name.
- Plots reported as Reports for BioSimulations compatibility.
- PubMed links restored in Annotations tabs.

identified in production and preparing the ground for the
